# 搭个伙 · 按菜分账

一起吃饭，但不一定每道菜都一起吃。把每道菜的金额和实际吃的人记下来，就能算出每个人该付多少。所有金额使用人民币，精确到分。

## 怎么用

1. 在「管理后台 → 聚餐成员」添加一起吃饭的人。成员会一直保留，之后可以随时增删改姓名与头像。
2. 回到「当前账单」，点「添加菜品/费用」，填写名称和金额，只勾选吃了这道菜的人，保存即可。
3. 每个人的应付金额立即更新，点姓名查看自己的菜品明细。

例如，青椒肉丝 ¥48 只有你和 A 吃，就只勾选你和 A，各付 ¥24。其他人不分摊这道菜。晚到的人加入名单后，不会自动分摊已经记下的菜；从下一道菜开始，按实际参与情况勾选。酒水、停车费等也可以按同样方式记。

每道菜的参与人互相独立。默认全选当前成员，取消没吃的人；也可以清空选择后只勾少数参与者。修改金额或参与人后自动重新计算。

开始下一顿饭时，管理员点「清空本次账单」并确认，清除菜品、费用与垫付记录，保留成员和登录账户。没有归档、定稿、继承选择或聚餐管理流程。

## 功能与权限

- 首页直接添加、修改菜品与分摊人，人物卡展示应付合计。
- 总费用、应付合计和差额始终显示；不足整除的一分按固定成员顺序依次分配，确保金额守恒。
- 有人先付钱时，可展开「垫付与结算」记录，作为辅助核对；不接入真实支付。
- 管理员管理成员、账户、页面和日志；编辑者可以新增、修改菜品、成员与垫付，删除及清空账单仅管理员可操作。
- 支持修改密码、管理登录会话、页面文字与图片编辑。

没有公开注册。当前账单允许访客查看，编辑与后台功能需要登录；完全私有使用时，请部署在受控网络或访问网关后。

## Docker Compose 部署

需要 Docker 和 Docker Compose v2。

1. 获取源码，执行 `cp .env.example .env`。
2. 编辑 `.env`，自行设置 `ADMIN_PASSWORD`（12–256 个字符的强密码）。不要提交 `.env`。
3. 启动：

```sh
docker compose up -d --build
docker compose ps
```

打开 `http://localhost:3000`。初始管理员用户名为 `admin`，密码由部署者配置，没有通用默认密码。初始密码只用于空数据目录；已有数据重启或更换初始化变量不会重设密码，后续在后台修改。

镜像以非 root 用户运行，根文件系统只读，运行数据保存在 `dinner-data` 命名卷。更新时保留此卷并执行 `docker compose up -d --build`。`docker compose down` 保留数据；带 `-v` 会删除命名卷，日常更新不要使用。

### 外网与 HTTPS

默认仅发布到本机。外网部署按环境配置 `BIND_ADDRESS`、`APP_PORT`、`PUBLIC_ORIGIN`。例如使用域名 `split.example` 时，可放在 HTTPS 反向代理后，设置 `PUBLIC_ORIGIN=https://split.example`。

Origin 必须与浏览器实际协议、域名和端口一致，代理须保留 Host。HTTPS 自动启用 Secure Cookie。不要信任任意客户端转发头；`TRUST_PROXY=loopback` 只信任应用进程的回环连接，普通跨容器代理不在范围内，Docker 默认不设置该变量。

## 本地开发

需要 Node.js 20 或更新版本。先通过环境变量设置 `ADMIN_PASSWORD`，再运行：

```sh
npm start
npm test
npm run check:version
npm run build
```

默认监听 `http://127.0.0.1:3000`，可用 `HOST`、`PORT`、`DATA_DIR`、`PUBLIC_ORIGIN` 配置。测试使用隔离临时目录和虚构凭据；`dist/` 发布目录不含运行数据。

密码以独立随机盐和 scrypt 哈希保存，JWT 密钥与登录会话持久化，退出或账户变化会撤销会话。Cookie 使用 HttpOnly、SameSite=Strict，HTTPS 下设置 Secure；写入校验 Origin、CSRF、权限与数据版本。

本仓库只有通用源码、测试、模板和原创 SVG，不包含运行账单、账户、上传图片、密钥、私人配置或部署者资料。
